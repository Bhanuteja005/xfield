# Xfield architecture

The reference projects informed the boundaries: Halden uses strict TypeScript, schema packages and separate validation commands; socialflyai and monorepo separate applications, shared contracts, storage and integration code. Xfield uses the same separation without importing their private application code or credentials.

- `apps/web`: React application, shared UI primitives and feature modules. Views are JSX; API access and shared domain contracts are strict TypeScript.
- `apps/api`: Cloudflare Worker API. Provider credentials stay in HTTP-only session cookies, all provider calls stay server-side, and every private query checks workspace ownership.
- `packages/shared`: Zod request contracts and domain types.
- `packages/db`: Drizzle schema. Generated migration files live in `drizzle` and are versioned.
- `tests`: API integration tests against an isolated workspace on the local Worker, plus contract tests.
- `recon`: Mobbin flow inventory and locally downloaded reference screens. Reference screenshots are excluded from publication; metadata records coverage.

Persistence uses D1 for metadata and R2 for uploaded/generated bytes. Guest ownership uses a random 128-bit workspace token in an HTTP-only cookie. This provides browser-continuity, not a recoverable cross-device account. Platform sign-in is displayed separately and does not imply guest-data migration.

Generation has explicit modes. Concept previews are procedural SVG compositions. Live image/video output uses documented Soul 2 and Seedance 2.0 endpoints. Other visible models and specialized tools have not been integrated with live APIs. Voice preview uses browser speech synthesis. Plans are illustrative, without checkout.

No provider generation is retried automatically after submission. Each submission carries an idempotency token. Failed and canceled requests remain visible. Cancellation calls the provider rather than merely stopping the polling UI.
